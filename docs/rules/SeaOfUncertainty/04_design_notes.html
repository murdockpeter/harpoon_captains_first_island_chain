Design Notes • Current Assessment

Is This One Game?

A candid snapshot of what currently feels strongest, what remains questionable, and what should be proven at the table before the design expands.

Current Answer

Yes — mostly. There is one strong game emerging around Mission → Time → Information → Command Intervention → Movement → Search → Combat → Friction → New Information. The remaining work is to make every subsystem speak that same mechanical language.

Strongest Mechanics

MechanicConfidenceWhy it belongs
Asynchronous Ready Time★★★★★Turns tempo into a real operational resource.
Standing Mission Orders★★★★★Lets players command organizations instead of repeatedly “activating units.”
Friction expressed through time★★★★★Creates consequences without a giant random-event subsystem.
Physical maneuver + tangible combat★★★★★Preserves the essential pleasure of a naval wargame.
Synchronization★★★★☆Potentially the signature operational decision.
Information aging★★★★☆Makes reconnaissance a continuous contest rather than a binary reveal.

Most Questionable Mechanics

Command Attention

The concept is strong; the exact implementation is not yet proven. Generic “Command Points” risk becoming abstract currency. Command Slots are better because they represent finite attention, but we still need to test whether slots create interesting prioritization rather than tedious assignment.

Entropy / Cohesion

Entropy is now restored as an explicit core system, but not as a generic morale bar. It represents physical capability that remains present yet is temporarily unavailable because friction, disruption, destruction, exhaustion, and mission churn interfere with effective action.

The current prototype direction uses an Entropy State of Low / Moderate / High / Critical, while preserving visible causes. Cohesion remains the concise execution-state summary: Cohesive / Disrupted / Disorganized. This is promising, but it must be tested to ensure that two linked state systems do not create needless marker burden.

Contact Model

A single detection ladder was too gamey. Location certainty + identity certainty + age feels more faithful and more decision-rich. It still needs a fast tabletop procedure so the information game does not become marker administration.

Universal Resolution

The earlier “2d6 + modifiers” concept is useful as prototype scaffolding but is too generic to define the final game. The intended resolution philosophy is now bounded uncertainty: decisions first establish a result band, then a small die result determines the exact outcome.

Command Network

This is the subsystem most likely to become a separate mini-game. Communications should matter only through three consequences: what you know, when you know it, and what orders you can transmit. If we start tracing packet routing, we have gone too far.

Logistics / Endurance

Endurance belongs only if it feeds the core engine. It should change time, friction, movement, and readiness — not create a detached logistics accounting game.

The Unifying Mechanical Language

Every future rule should change one or more of these variables:

VariablePlayer-facing question
TimeWhen can I act?
PositionWhere can I influence the fight?
InformationWhat do I believe is happening?
CommandWhat can I deliberately change or coordinate?
Entropy / CohesionHow much physical potential is unavailable, and how effectively can the formation execute?
Physical CapabilityWhat can this force actually do?

What Must Never Be Lost

Move Things Around

Operational hexes, screens, patrol lines, flanking, standoff distances, chokepoints, and positioning are not ornamental. They are central player actions.

Pew Pew Pew

Detection, target selection, weapon commitment, defense, leakers, damage, and force preservation must remain dramatic and satisfying.

Prototype Test

The next real test should be deliberately small but kinetic:

  • Blue: 1 Carrier Group, 1 SAG, 1 SSN, 1 land-based air group.
  • Red: same.
  • Approximately 12 × 10 operational hexes.
  • 12–16 operational Time spaces.
  • One clear operational objective, such as protecting or preventing an amphibious transit.
  • Only enough rules for movement, detection, command, time, strike, air defense, submarine attack, damage, and recovery.

Questions the Prototype Must Answer

  • Do I repeatedly face 2–4 legitimate choices, or is one option obvious?
  • Do I care that my information is old?
  • Do I feel tension between acting now and preparing better?
  • Is synchronization always worth waiting for? If yes, redesign it.
  • Do Command Slots create prioritization or chores?
  • Does Entropy create meaningful decisions, or does it merely add markers and penalties?
  • Can I usually explain why a formation has high Entropy?
  • Do Mission Orders preserve agency or remove too much direct control?
  • Do I physically move pieces enough to feel like a naval wargame?
  • Does combat provide satisfying “how many got through?” moments?
  • Can I explain a loss in terms of decisions rather than dice?
The decisive test: when three plausible choices are in front of the player, do they have to think hard about which one to take?

Source Lineage

The design is inspired by the Perla-led framework’s emphasis on the six dimensions of wargaming, the interaction of operational / information / command topologies, friction and uncertainty, command as a countervailing force, and the importance of time and synchronization. The current rules deliberately translate those ideas into a hobby-boardgame structure rather than reproduce the paper’s example game.
